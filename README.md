I build intentionally [Vulnerable Web Apps](https://offensive360.com/blog/what-is-a-vulnerable-web-application/) to learn and teach web security — realistic, dockerized products, each hiding a specific flaw from the [OWASP Top 10](https://owasp.org/www-project-top-ten/).

Each lab is meant to be broken and then fixed: I attack it with [Burp Suite](https://portswigger.net/burp), [OWASP ZAP](https://www.zaproxy.org/) and [Nmap](https://nmap.org/), then wire the findings back into the pipeline so the vulnerability can't sneak back in.

I build full-stack apps as [Turborepo](https://turborepo.com/) monorepos, each shipping with a complete
delivery pipeline — [GitHub Actions](https://github.com/features/actions),
[Release Please](https://github.com/googleapis/release-please) for automated semantic
versioning and [GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow). 

Mostly working with [TypeScript](https://www.typescriptlang.org/), [Node.js](https://nodejs.org/) / [NestJS](https://nestjs.com/) and [React](https://react.dev/) on the app side, [AWS](https://aws.amazon.com/), [Terraform](https://www.terraform.io/) and [Kubernetes](https://kubernetes.io/) on the infra side, wired together with a DevSecOps toolchain ([SonarQube](https://www.sonarsource.com/products/sonarqube/), [Trivy](https://trivy.dev/), [Snyk](https://snyk.io/), [Semgrep](https://semgrep.dev/), [OWASP ZAP](https://www.zaproxy.org/)).

Keeping an eye on everything with [Prometheus](https://prometheus.io/), [Grafana](https://grafana.com/) and [OpenTelemetry](https://opentelemetry.io/).
